# Axiom EventStore Service

The Axiom EventStore service submits events to [Axiom](https://axiom.co) using their official Go SDK.

## Configuration

To use the Axiom EventStore service, configure it in your YAML configuration file:

```yaml
eventstore:
  type: axiom
  dataset: # The name of the Axiom dataset to send events to
    type: env  # or "text" for direct value
    value: AXIOM_DATASET  # Environment variable name or direct dataset value
  token:
    type: env  # or "text" for direct value
    value: AXIOM_TOKEN  # Environment variable name or direct token value
```

### Configuration Fields

- `type`: Must be `"axiom"` to use this service
- `dataset`: The name of the Axiom dataset where events will be sent. Defaults to `"qtap-events"` if not specified
  - `type`: Either `"env"` (to read from environment variable) or `"text"` (direct value)
  - `value`: Environment variable name (if type is `"env"`) or the actual token (if type is `"text"")
- `token`: The Axiom API token configuration
  - `type`: Either `"env"` (to read from environment variable) or `"text"` (direct value)
  - `value`: Environment variable name (if type is `"env"`) or the actual token (if type is `"text"")

## Environment Setup

If using environment variable for the token:

```bash
export AXIOM_TOKEN="your-axiom-api-token"
```

## Supported Event Types

The service supports the following event types from the `eventstore` package:

- `*eventstore.Connection` - Connection Audit Log
- `*eventstore.Request` - HTTP request events
- `*eventstore.Issue` - Error/issue events
- `*eventstore.PIIEntity` - PII detection events
- `*eventstore.ArtifactRecord` - Artifact storage records

## Metrics

The service exposes the following metrics:

- `tap_axiom_records_submitted`: Total number of records submitted to Axiom
- `tap_axiom_records_ingested`: Total number of records successfully ingested by Axiom
- `tap_axiom_records_failed`: Total number of records that failed to be ingested by Axiom

## Error Handling

The service includes robust error handling:

- Validation of required configuration (API token)
- Graceful handling of unsupported event types
- Detailed error logging for failed submissions
- Metrics tracking for monitoring ingestion success/failure rates

## Example Usage

Once configured, the service will automatically receive and submit events as they are generated by the application. No additional code changes are required - the service integrates with the existing eventstore infrastructure.
